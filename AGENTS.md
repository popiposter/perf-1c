# Правила разработки perf-1c

## Назначение

Развиваем локальный диагностический комплект для 1С + MS SQL Server на основе реальных инцидентов. Сначала прочитайте `README.md`, `README_RU.md` и `docs/roadmap.md`.

Не предполагайте имя, топологию и версии проблемного сервера до получения фактических данных. Примеры команд не являются реквизитами действующей инфраструктуры.

## Инварианты

- Сбор по умолчанию только читает диагностические источники и пишет собственные локальные результаты. Не добавляйте автоматическое обслуживание, изменение настроек, очистку кэшей, завершение сеансов или включение трассировок.
- Изменение состояния сервера, временное логирование и исправления отделяйте от read-only-профиля; нужны явное поручение оператора, ограниченная область действия и план возврата.
- Ошибка, отсутствие прав, усечение, пропуск и несовместимая версия означают недостаток данных, а не отсутствие проблемы.
- Накопительные счётчики анализируются по приращениям с контролем перезапусков, пропусков, идентичности объектов и единиц измерения. Отсутствие операций не равно нулевой задержке.
- Разделяйте измерение, гипотезу и подтверждённую причину. Сохраняйте время, источник и область действия каждого вывода.
- Ограничивайте время запросов, объём результатов, длительность и размер сбора. Измеряйте воздействие сборщика на реальном пилоте.

## Реализация и проверки

Основная цель сборщика: PowerShell 7 x64 на Windows; сохраняйте локальную совместимость с Windows PowerShell 5.1. Загрузчик `Start-OneCPerf.ps1` требует PS7. Анализатор: Python 3.10+ со стандартной библиотекой. Сохраняйте UTF-8 BOM у `Collect-OneCPerf.ps1`. Не добавляйте обязательные серверы, облако или инфраструктуру без практической необходимости.

Загрузчик скачивает только код по HTTPS, фиксирует commit SHA и запускает его в текущем PS7. Не добавляйте Invoke-Expression, автоматический обход ExecutionPolicy, отключение TLS-проверок или скрытый переход в powershell.exe. Код и результаты храните отдельно; не запускайте оставшуюся старую копию после ошибки загрузки. Хеш из того же источника не является независимой проверкой подлинности.

Базовые целевые проверки:

```powershell
python -m unittest discover -s tests -v
pwsh -NoProfile -File .\tests\Test-PowerShell.ps1
```

Добавляйте целевые тесты на изменённое поведение, без дублирующих больших прогонов. Тесты Python и синтаксиса PS не заменяют проверки PowerShell/CIM/SQL. В отчёте о работе явно разделяйте выполненные проверки и непроверенные предположения. До реального пилота не объявляйте сборщик production-ready. Не включайте платные или длительные CI-процессы без отдельной необходимости.

## Данные и документация

Репозиторий публичный. Не коммитьте и не публикуйте в Issues реальные замеры, журналы, планы с чувствительными значениями, пароли, резервные копии или данные заказчика. Для тестов используйте синтетические либо проверенные обезличенные примеры. `.gitignore` не заменяет проверку staged-файлов. Не отправляйте диагностические данные во внешние сервисы автоматически.

Обновляйте документацию вместе с поведением. `SHA256SUMS.txt` фиксирует исходный импорт 0.1 и не является проверкой неизменности текущей ветки после доработок; для нового релизного комплекта формируйте новый манифест.

# От измерений к конкретному запросу

Анализатор 0.2.0-pilot дополняет сборщик 0.1.3-pilot; формат исходного архива не меняется.
Проверочный архив подтвердил успешную работу базовых Windows/SQL-источников в одном окружении.
Это не сертификация всех версий Windows, PowerShell, SQL и не подтверждение малой нагрузки везде.

## Автономный разбор

```powershell
python analyze.py PATH_TO_CAPTURE.zip --output analysis-output
```

`workload.py` группирует мгновенные наблюдения по базе, query_hash, плану и клиентскому процессу.
Показывает число наблюдений, максимум одновременно видимых запросов и независимые максимумы
CPU/возраста запроса. Не суммирует накопленные CPU/elapsed по повторным снимкам; наблюдения
не равны числу завершений, а одинаковый hash не доказывает одинаковые параметры.
Идентификаторы баз связываются с именами, локальный PID — с отдельным снимком версии процесса.
При неоднозначном имени базы или удалённом хосте привязка не придумывается.

Выбранная база — не фильтр общесерверной нагрузки. Отчёт предупреждает о запросах других баз.
Очереди SQL и memory grants показываются отдельно, без автоматического приписывания группе запросов.
Внутренние SOS_WORK_DISPATCHER/SQLTRACE_INCREMENTAL_FLUSH_SLEEP вынесены в раскрываемую таблицу,
не удалены из исходных данных и не объявлены безвредными. CXPACKET/CXCONSUMER сохранены
с предупреждением, что параллелизм — не самостоятельный диагноз.

## Точечный сбор текста и cached plan

Новый `Get-OneCQuery.ps1` — отдельный PS7 Windows x64 сценарий для SQL Server 2016+.
Он не устанавливает модули, не запускает бизнес-запрос, не очищает кэш, не включает Query Store/XE.
Требует имя SQL-базы и конкретный query_hash из отчёта; пароль можно передать только PSCredential.
По умолчанию Windows auth и проверка SQL-сертификата. TrustServerCertificate — только явный параметр.

```powershell
& { $s=Join-Path $env:TEMP ('perf-query-'+[guid]::NewGuid()+'.ps1'); Invoke-WebRequest 'https://raw.githubusercontent.com/popiposter/perf-1c/main/Get-OneCQuery.ps1' -OutFile $s -ErrorAction Stop; & $s -SqlInstance 'SQL_HOST' -Database 'DB_NAME' -QueryHash '0x1111111111111111' -IncludeSqlText -IncludePlan }
```

Это примеры, не параметры какого-либо сервера. Для воспроизводимого запуска замените `main`
в URL на проверенный commit SHA. Сам сценарий не скачивает никаких дополнительных файлов.
Фиксируется SHA256 исполняемого файла. ExecutionPolicy и TLS не меняются автоматически.

**Планы тоже содержат SQL-текст, литералы и значения параметров.** Оба флага разрешают сбор
соответствующего чувствительного содержимого. Без флагов сохраняются только метаданные
завершённых выполнений из кэша. Результат не обезличен, не зашифрован и не предназначен
для публичного Git/Issues. Текст извлечённых запросов никогда не выполняется.

Метаданные выбираются по query_hash и dbid атрибута плана текущей базы, до трёх записей
(настраиваемо 1–10). Сначала ограничивается список, потом по конкретным handles читаются
текст оператора и план. Таймаут каждого запроса 3 секунды (настраиваемо 1–15); запросы к
каталогам кэша не являются бесплатными и могут завершиться по таймауту. Текст ограничен
65536 символами, план — 2097152; усечение помечено в JSON и имени файла. Пустой/вытесненный
план и ошибки не становятся успешным нулевым результатом. Все операции синхронные.

Результат: отдельный `query_*.zip` под `%LOCALAPPDATA%\perf-1c\captures`, JSON со статусами
и, при согласованном сборе, `.sql` и `.sqlplan`. Ничего не отправляется автоматически.
`not_found` может означать вытеснение плана, перекомпиляцию или отсутствие завершённых
выполнений в кэше. Повторите сбор после проблемной операции, не очищая кэши.

Статистики кэша — **за время жизни скомпилированного плана**, не за минутный диагностический
интервал. Сохраняются время компиляции/последнего старта, счётчик завершений, CPU/elapsed
в микросекундах, чтения, DOP, последнее выделение/использование memory grant.
Cached plan содержит оценки компиляции, **не actual execution plan** и не фактическое
число строк в операторах. Для причин ошибок оценок может понадобиться следующий уровень диагностики.

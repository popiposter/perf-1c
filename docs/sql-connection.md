# Диагностика подключения SQL

Проверка доступности диагностических источников — не диагностика медленной операции 1С.
Ошибки подключения не интерпретируем как ожидания, блокировки или неисправность дисков.

## Недоверенная цепочка сертификата

Известные сообщения:

```text
The certificate chain was issued by an authority that is not trusted.
Цепочка сертификатов выпущена центром сертификации, не имеющим доверия.
```

Сборщик явно использует `Encrypt=True` и по умолчанию `TrustServerCertificate=False`.
При этой ошибке клиент не смог проверить доверие сертификату SQL. Из неё нельзя узнать,
самоподписанный ли это сертификат, отсутствует ли промежуточный сертификат или доверенный
корневой CA: для этого нужна отдельная проверка сертификата администратором.
Она также не доказывает успешный вход, наличие нужных DMV-прав или доступность выбранной базы.

**Предпочтительный постоянный вариант:** администратор настраивает сертификат SQL,
проверяет срок, подходящее имя сервера, полную цепочку CA и доверие клиента к корню CA.
Не импортируйте неизвестные сертификаты в доверенные корневые автоматически.
Изменение сертификатов и SQL-конфигурации не выполняется диагностическим сборщиком.

**Временный вариант для диагностики:** после проверки целевого узла оператор явно добавляет
`-TrustServerCertificate` к команде сборщика или загрузчика. Например, для проверенного
локального экземпляра по умолчанию, запуская из каталога скачанного комплекта:

```powershell
.\Collect-OneCPerf.ps1 -SqlInstance '.' -Minutes 1 -TrustServerCertificate
```

`.` здесь — пример, не обнаруженная инфраструктура. Для удалённого экземпляра особенно
важно проверить целевой узел: флаг отключает проверку его подлинности по сертификату.
Шифрование сохраняется, но защита от подмены сервера ослабляется. Это не эквивалент
корректно настроенному сертификату. Не добавляйте флаг всем запускам по умолчанию.

Флаг относится только к соединениям SQL данного процесса. Он не отключает TLS-проверку
скачивания с GitHub, не меняет настройки сервера и не создаёт постоянного доверия Windows.
Удаление флага в следующем запуске возвращает проверку сертификата. Перезапуск SQL
для применения этого клиентского параметра не нужен.

## Чего не делать

Не выключать `Encrypt`, не менять глобальные проверки HTTPS и не выдавать `sysadmin`
ради исправления ошибки сертификата. Не считать любой сбой `SSL Provider` недоверием CA:
сбой протокола, несовпадение имени и другие проблемы могут требовать другого решения.
Не считать отсутствие ошибок Windows доказательством полноты SQL-части.

## Обратная связь в 0.1.3

Сборщик распознаёт только приведённые русское/английское сообщения в SQL-источниках,
сохраняет исходную ошибку и добавляет `error_kind` и `suggested_action`.
Общая подсказка не повторяется для каждого каталога и выводится в `coverage.html`.
Это классификация текста ошибки, не исследование сертификата.

Явный выбор `-TrustServerCertificate` сопровождается предупреждением. Повторного
подключения с изменёнными параметрами без команды оператора нет. Подсказки не меняют
поведение остальных источников: сбор Windows продолжается, а ошибки SQL видны по каждому
источнику. После завершения нужна проверка `coverage.html` и исходных статусов.

Нужны успешные `sql.instance`, `sql.permissions`, `sql.epoch`, `sql.waits`, `sql.io`
и другие ожидаемые источники. Счётчик `sql_runtime_sample_count` отражает лишь число
успешных `sql.epoch`, не полноту всех SQL-данных. Наличие ZIP и `completed` недостаточно.

## Первичные источники

- [Microsoft: System.Data.SqlClient TrustServerCertificate](https://learn.microsoft.com/en-us/dotnet/api/system.data.sqlclient.sqlconnectionstringbuilder.trustservercertificate?view=netframework-4.8.1).
- [Microsoft: certificate chain not trusted](https://learn.microsoft.com/en-us/troubleshoot/sql/database-engine/connect/certificate-chain-not-trusted). Статья о смене драйверов; здесь используем объяснение доверия и вариантов исправления, не делаем вывод о смене драйвера на конкретном сервере.

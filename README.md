# perf-1c

Локальный инструментарий диагностики производительности **1С + Microsoft SQL Server**.
Связываем замедление пользователя с измерениями Windows, SQL Server и 1С;
отделяем факты от гипотез и проверяем эффект изменений.

**Версия: 0.1.3-pilot.** Добавлены распознавание недоверенной цепочки сертификата SQL,
подсказка оператору в консоли и `coverage.html`, структурированное описание ошибки.
Это не автоматическое исправление сертификата. Windows-сбор подтверждён пилотом;
полноценный SQL-сбор ещё не подтверждён. Это диагностический комплект, не оптимизатор.

## Одна команда в PowerShell 7

Откройте **PowerShell 7 x64 (`pwsh.exe`) на Windows**. Первый запуск на одну минуту:

```powershell
& { $s = Join-Path $env:TEMP ("perf-1c-" + [guid]::NewGuid() + ".ps1"); Invoke-WebRequest 'https://raw.githubusercontent.com/popiposter/perf-1c/main/Start-OneCPerf.ps1' -OutFile $s -ErrorAction Stop; & $s -Minutes 1 }
```

Будут запрошены экземпляр SQL и имя SQL-базы. Enter для экземпляра означает `.`
(локальный экземпляр по умолчанию), Enter для базы — пропустить детали конкретной базы.
Используется Windows-аутентификация текущего пользователя. Полные требования и права:
[README_RU.md](README_RU.md).

Для среза во время проблемы замените в конце `-Minutes 1` на `-Minutes 10 -IncludeMaintenance`.
Без вопросов, с известными параметрами, в конце команды используйте, например:

```powershell
& $s -SqlInstance 'SQL_HOST\INSTANCE' -Database 'DB_NAME' -Minutes 10 -IncludeMaintenance -NonInteractive
```

Это фрагмент **внутри блока исходной команды**, вместо `& $s -Minutes 1`;
`SQL_HOST\INSTANCE` и `DB_NAME` — примеры, не параметры вашего сервера.
На отдельном сервере 1С используйте `& $s -SkipSql -Role onec -Minutes 10`.

Код скачивается в новый подкаталог `$env:LOCALAPPDATA\perf-1c\downloads`,
а замеры — в `$env:LOCALAPPDATA\perf-1c\captures`. Путь к ZIP выводится после сбора.
Прежние результаты не перезаписываются. Git, Python и модуль SqlServer на сервере не нужны.
Сборщик выполняется в текущем PS7; локальный запуск в Windows PowerShell 5.1 также сохранён.

Загрузчик разрешает `main` в конкретный commit SHA, скачивает комплект этой версии,
записывает источник и хеш архива, затем запускает сборщик. Для фиксации версии используйте
`-Ref <40-символьный SHA>` и тот же SHA вместо `main` в URL загрузчика.
`-DownloadOnly` позволяет сначала скачать и проверить код без сбора данных.
Это доверие к коду вашего репозитория по HTTPS, а не независимая проверка подписи.
Нужен доступ к raw.githubusercontent.com, api.github.com и codeload.github.com.

**Нет** автоматического изменения ExecutionPolicy, отключения проверки сертификатов,
установки служб, повышения привилегий или отправки результатов.
При корпоративном запрете скриптов используйте согласованный порядок их запуска.

## SQL: недоверенная цепочка сертификата

Сообщение «Цепочка сертификатов выпущена центром сертификации, не имеющим доверия»
означает отказ при проверке доверия сертификату. Это не прежняя ошибка `DataSource`
и не установленная причина медленной работы. Права пользователя и SQL-настройки
при таком отказе ещё не проверены.

Предпочтительный вариант — настроить проверяемый сертификат SQL и доверенную цепочку CA.
Для временного диагностического подключения к **заранее проверенному доверенному узлу**
оператор может явно добавить `-TrustServerCertificate` в конец команды запуска сборщика.
При этом `Encrypt=True` сохранён, но подлинность сервера по сертификату не проверяется.
Такой режим не защищает от подмены сервера и не должен становиться постоянной настройкой.
Проверки HTTPS при скачивании кода, хранилище сертификатов Windows и настройки SQL
не изменяются. Автоматического повторного подключения с ослабленной проверкой нет.

В 0.1.3 известное сообщение на русском/английском получает `error_kind=sql_certificate_untrusted`.
Общая подсказка печатается один раз, записывается в манифест и `coverage.html`;
исходные ошибки каждого источника сохранены. Классификатор намеренно не относит
любой `SSL Provider`, ошибку входа, таймаут или нехватку прав к недоверию сертификату.
Подробнее: [Диагностика подключения SQL](docs/sql-connection.md).

## Исправление SQL-подключения в 0.1.2

В 0.1.1 источники SQL могли завершаться ошибкой `Keyword not supported: 'DataSource'`.
Это ошибка построения строки подключения в сборщике, до открытия соединения,
а не доказательство неправильного имени сервера, нехватки прав или ошибки сертификата.

Используются канонические ключи `SqlConnectionStringBuilder`: `Data Source`,
`Initial Catalog`, `Integrated Security` и остальные параметры. Конструктор вынесен
в `New-OneCPerfSqlConnection`, чтобы тест проверял реальный путь создания строки,
а не только наличие класса `SqlConnection`. Шифрование и проверка сертификата
по умолчанию сохранены; пароли не помещаются в строку подключения.

Ошибки источников сразу видны в консоли. В конце выводится предупреждение,
если SQL runtime не собран. `stop_reason=completed` означает завершение по таймеру,
**не полноту данных**. Проверяйте `coverage.html`, а не только наличие ZIP.
В манифест добавлены PID сборщика, число ошибок источников и число успешных `sql.epoch`
(`sql_runtime_sample_count`); последнее не гарантирует успех остальных SQL-источников.
Версия сборщика и commit SHA выводятся при запуске.

После обновления повторите минутный сбор. В `coverage.html` нужны успешные `sql.instance`,
`sql.permissions` и runtime-источники (`sql.epoch`, `sql.waits`, `sql.io`, `sql.requests` и другие).
При новой ошибке сначала разберите её; не отключайте автоматически проверку сертификата
и не выдавайте sysadmin ради диагностики.

## Структура

- `Start-OneCPerf.ps1` — загрузка и запуск из PS7.
- `Collect-OneCPerf.ps1` и `sql/` — ограниченный сбор; `analyze.py` — автономный отчёт.
- `tests/` — целевые проверки; `docs/case-template.md` — карточка инцидента.
- `docs/roadmap.md`, `docs/sources.md`, `AGENTS.md` — развитие, источники и правила.
- `SHA256SUMS.txt` — контрольные суммы исходного импорта 0.1, не изменённой версии.

## Проверки

```powershell
python -m unittest discover -s tests -v
pwsh -NoProfile -File .\tests\Test-PowerShell.ps1
pwsh -NoProfile -File .\tests\Test-SqlConnection.ps1
pwsh -NoProfile -File .\tests\Test-SqlErrorHints.ps1
```

Python проверяет анализатор. `Test-PowerShell.ps1` проверяет синтаксис и логику загрузчика
с подменённой сетью, а на Windows — создание SQL-провайдера без соединения.
`Test-SqlConnection.ps1` на Windows вызывает реальный конструктор сборщика: Windows/SQL auth,
оба значения TrustServerCertificate, таймаут, экранирование имени базы и отсутствие пароля
в строке подключения. Он не открывает SQL, не читает CIM и использует только синтетические данные.
Его также можно запустить в Windows PowerShell 5.1.

`Test-SqlErrorHints.ps1` проверяет русское/английское сообщение, отрицательные примеры,
реальный путь обработки ошибки с подменой вывода и единственную общую подсказку.
Этот тест не требует Windows, SQL, сети или Pester; entry point сборщика не выполняется.

В среде подготовки 0.1.3 PowerShell отсутствует: 12 Python-тестов прошли,
PowerShell-тесты не выполнены. Повторный SQL-пилот не заменяется автономными тестами.
CI автоматически не включается.

## Диагностические данные

**Репозиторий публичный; замеры — нет.** Не публикуйте реальные архивы, журналы,
SQL-планы, резервные копии, пароли или сведения заказчика в Git и Issues.
`.gitignore` не заменяет проверку содержимого. Перед передачей ZIP проверьте его:
он не обезличен и не зашифрован. Автоматической выгрузки данных нет.

Метрики Windows относятся к узлу запуска. Для разных серверов SQL и 1С нужны отдельные
сборы с одним `CaseId`. Сбор → проверка полноты → гипотезы → точечная диагностика →
согласованное изменение → сравнение до/после.
